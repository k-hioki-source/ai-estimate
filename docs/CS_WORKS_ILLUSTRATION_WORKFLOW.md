## 動作

正式見積りで採用した明細から、1行につき1点の制作対象を作る。AI概算の計算は変更しない。
新しい発注では自動作成する。既に発注・制作開始済みの案件は管理者が「発注明細から制作一覧を準備」を押して明示的に開始する。既存案件を一括変換しない。
各点に独立した稿、確認依頼、画像赤入れ、承認・修正状態を持つ。複数点の確認依頼や結果送信をまとめられ、承認と修正依頼を混在できる。
承認済みの点は固定し、修正対象だけ新しい稿をアップロードする。新稿に過去のコメント・赤入れを引き継がない。提出済みの確認履歴は閲覧専用。
全点が承認された時だけ案件を承認済みにする。納品・請求は従来どおり案件単位で、採用見積りの固定金額を維持する。

## 実装と権限

追加migrationは `supabase/migrations/20261027010000_illustration_workflow.sql`。
制作対象・稿・操作記録を追加し、既存確認履歴に対象の点を紐付ける。従来案件の確認操作を維持し、新方式では案件単位の旧操作による迂回を拒否する。
API `app/api/cs-works/illustrations/route.ts` と検証付きRPCはユーザーJWTを使い、管理者・所有顧客・対象稿・確認状態をDBで検証する。新テーブルの直接書き込みは許可しない。
`IllustrationWorkflow.tsx` を管理者・顧客案件画面へ組み込み、既存資料欄、納品・請求操作、共有・プレビューを維持する。
既定無効の `NEXT_PUBLIC_CSWORKS_ILLUSTRATION_WORKFLOW` を追加。初期化済み案件でフラグが無効の場合は利用不可を表示し、従来の案件単位操作へ戻さない。
同一操作IDの再送を検証し、まとめて行う確認結果はトランザクションで確定する。競合時は入力を残して再取得を案内する。
一部だけの承認通知で案件全体の承認と誤って案内しない。既存メール送信経路を利用し、操作記録の送信者・案件・通知種別を照合する。

## 制限

アップロードはPNG/JPEG/PDF・50MBまで。PDFへの赤入れ、承認済みの点の再開、発注後の明細変更は含めない。
StorageアップロードとDB登録は単一トランザクションではない。登録再試行に同じ操作IDを使うが、中断時の非公開Storage孤立ファイルを自動削除しない。
メールはDB確定後に送信し、失敗時の自動再送・配送保証は含めない。共有リンクは従来どおり元ファイルを公開し、赤入れを公開しない。
