# AI見積り検証（2026-11-15）

## 目的と公開範囲
管理者 `/admin/estimate-quality` に、任意の同意がある匿名概算だけを一時保存する。〇／要修正、適正工数、任意の線画・彩色内訳、修正理由を記録する。モデル学習・自動ルール変更・過去見積りの書換えはしない。

## 記録
- opt-in `quality-review-7d-v1`（初期未選択）。正式見積り希望・メール入力ありは対象外。
- 画像、依頼文、条件、補正前/後の解析、3方式、価格、エンジンcommit SHA。
- 取得した会社名・氏名・メールの項目は検証テーブルへ複製しない。ただし依頼文中の情報は7日間の記録に含まれる。
- 同意した検証対象の通知メールはID・時間・金額・管理画面リンクのみ。画像、依頼文、AI自由記述を転載しない。
- 7日後はAPIから閲覧・更新不可。`csworks-quality-review-expiry` が15分毎に専用テーブルの期限切れ行を削除。画像も同じ行に保持するので孤立ファイルなし。更新しても期限を延長できない。
- 画像は圧縮済みデータ（最大約3MB相当）、JPEG/PNG/WebPのみ。既存案件・保存済み見積り・Storage・従来メールは対象外。
- 従来の「一定時間後に自動削除」という全般的な案内は、メール添付まで削除する実装ではなかった。新案内で検証用の期限と別扱いを明確化。

## セキュリティ
新テーブルはRLS有効、anon/authenticatedの全権限なし、service_roleのみ。管理者APIはgetUserとprofiles.role=adminを検証。キャッシュ禁止、署名URLなし。PATCHはrevisionで競合拒否、期限フィルターあり、期限・原本の編集不可。
Supabase advisorの新テーブルについてのINFO「RLS有効・ポリシーなし」は、ブラウザに一切公開しない意図どおりの構成。既存リソースの警告は変更しない。

## 運用
日々の要修正を管理画面で記録する。開発担当には「AI見積り検証の要修正を確認して」と依頼し、期限内の記録を読み取って改善候補を作る。本番に個別パッチを即適用せず、既存〇ケースとの比較を行う。
原本は7日で消えるため、長期の画像回帰基準は会社所有または別途許諾済みの画像で別に整備する。管理画面のJSONは表示中ページの数値・判定・エンジン版だけを出力し、原画像・依頼文・自由記述は含めない。

## 検証
- API/ロジック: opt-in、認証拒否、期限、入力検証、合計工数、競合拒否、保存失敗時の見積り継続、メールへの内容非転載のモック試験。
- 実DB: 本番の新テーブルだけに合成行をトランザクション内で挿入し、7日期限と延長拒否を確認、ROLLBACK。ブラウザ権限なし・cron active確認。
- 専用テストDBは接続タイムアウトで利用できず、本番の新専用テーブルの合成トランザクションで代替。既存顧客の行は読み書きしない。
- 実画像を実AIへ送信する試験、7日経過した実データの削除確認、管理者サインイン後の本番クリック試験とは区別する。
